# Minimum compatibility bridge (Prompt 6)

`Port.Bridge` implements the exact missing metadata surface in the pinned original DLL: 19 GamerServices, Windows Phone, sensor, and vibration types, with 45 referenced members. The bridge uses the same namespace/type names but lives in the authored `Port.Bridge` assembly. `GamerServicesComponent` derives from FNA's `GameComponent` and attaches state to its owning `Game` instance. `SignedInGamer` derives from `Gamer`; its collection derives from `ReadOnlyCollection<SignedInGamer>` so the original call shapes remain valid. The three referenced value types that represent keys/icons/content categories are enums with no inferred named values or desktop behavior.

The component's construction, guide visibility, screen-saver flag, task content-type storage, event subscription, and vibration-controller identity have local state or identity semantics. The desktop policies are one local non-Live gamer, an idempotent accelerometer start that warns no sensor readings will arrive, and full-game mode for the user-supplied supported XAP (`Guide.IsTrialMode=false`, `Guide.SimulateTrialMode=false`). The running original `TrialMgr.trial` field was observed false. This desktop policy does not validate a phone license. Local achievements reflect the game's saved profile flags; offline leaderboards return an empty result. Message boxes and accelerometer readings still throw `BridgeApiUnavailableException` if reached. Marketplace requests display an unavailable notice, and vibration requests report absent hardware once and let play continue. See [offline services](../runtime/offline-services.md) and [media and phone behavior](../runtime/media-phone-behavior.md).

The updated ABI checker accepts `--bridge` to verify the full target signatures and inheritance against the built bridge. The commands below use the current bridge hash and ABI report. Run from the repository root:

```powershell
./scripts/build-offline.ps1
dotnet run --no-build -c Release --project tools/abi_check -- --inventory generated/evidence-from-xap.json --dll private/preparation-net10/original-xap/ZombiesWP7.dll --fna out/deps/managed/FNA.dll --bridge src/Port.Bridge/bin/Release/net10.0/Port.Bridge.dll --output generated/abi-report-bridge-net10.json
dotnet run --no-build -c Release --project tools/prepare-cli -- rewrite --xap 'game/Z0MB1ES (on teh ph0ne) v1.0.0.0.xap' --dll private/preparation-net10/original-xap/ZombiesWP7.dll --abi-report generated/abi-report-bridge-net10.json --fna out/deps/managed/FNA.dll --bridge src/Port.Bridge/bin/Release/net10.0/Port.Bridge.dll --output private/prepared/bridge-check-net10
dotnet run --no-build -c Release --project src/Port.Launcher -- --check-load private/prepared/bridge-check-net10/ZombiesWP7.dll
dotnet run --no-build -c Release --project tests/Bridge.Checks
```

The ABI report resolves all 146 external type and 382 member references, with zero unresolved types, members, virtual slots, inheritance relationships, or generic method instantiations. Its overall validation status is still `fail` because `IsolatedStorageFile.GetUserStoreForApplication` needs the later desktop save behavior rewrite. The rewriter pins the current bridge report and its exact bridge DLL hash. The launcher loads and enumerates 177 game types (the original 178 TypeDefs include `<Module>`), reflects 1,966 members, and JIT-prepares all 818 method bodies without `FileNotFoundException`, `TypeLoadException`, `MissingMethodException`, or `InvalidProgramException`. Prompt 8 subsequently instantiated and ran `Game1` to the menu; this ABI check alone asserts only loadability and call shapes, not phone-service parity.
