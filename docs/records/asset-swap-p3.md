# Asset swap Prompt 3 — setup and Settings integration

## Player flow

The one-file Inno setup accepts the supported phone XAP, then offers one I MAED source (Steam or 360) and an independent Time Viking 360 source. Source pages show the recognized title/version and expected mapped coverage. The setup helper checks pinned executable and texture hashes for Steam or the complete pinned LIVE package hash for each 360 title before changing an installation. An omitted source is a valid phone-only install. A later run can keep, add, replace, repair, or remove either source independently. The helper stages verified crops and manifests under `current/optional-art/`; the original phone content and game DLL remain separate. Saves live outside the install directory.

The `ASSETS` Settings page has I MAED, TIME VIKING, ENDLESS, and BACK rows. Each row displays ORIGINAL, the installed source, or UNAVAILABLE. The first successful import is selected by default. A click toggles a verified source and writes `assets.json` beside the phone save; a missing or corrupt import renders Original and clicking it displays `IMPORT UNAVAILABLE. REPAIR IN SETUP.` Startup and Settings clicks recheck generation manifests and every imported PNG hash. The original phone game still draws every unmapped element, and Endless remains eligible only for 360 sources according to its P1 priority manifest. No game carousel or mode dispatch was changed.

## Implementation and boundaries

The setup payload includes a frozen Python importer, a self-contained 360 XNB decoder, pinned metadata-only mappings/inventories, and their license notices. It includes no source game executable, package, extracted content, or prepared art. The importer uses a private work directory during setup and writes only verified generated art to the install staging directory. The strict build allow-list and release audit cover the added tools and notices. `verify-installed` now checks every generated content-manifest output as well as the install manifest, so an update cannot reuse an incomplete phone content tree. A failed art validation leaves the prior installation current; a successful update commits staged output and the wizard retains its rollback backup until setup completes.
