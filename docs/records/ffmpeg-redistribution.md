# FFmpeg redistribution follow-up (2026-11-07)

The P4 installer contained a third-party static FFmpeg build that reported GPLv3 and linked several libraries whose matching source revisions were not established. That package was not published. To make the converter's source delivery verifiable, this follow-up builds a separate Windows FFmpeg 8.1.1 executable from pinned upstream revision `239f2c733d`, libogg 1.3.6, and libvorbis 1.3.7. The [build recipe](../../installer/ffmpeg/README.md) pins all three source archive hashes and the Docker base image digest. It disables GPL and nonfree components; `ffmpeg -L` reports LGPL 2.1 or later. The port's authored code remains GPLv2.

The Windows executable SHA-256 is `e2e148a514b188a08102ec71c03f970ad1273316fab430e4c95065b0650fb306` (21,469,696 bytes). Its import table lists only `bcrypt.dll`, `KERNEL32.dll`, `msvcrt.dll`, and `SHELL32.dll`; there is no `libwinpthread-1.dll` dependency. `config/content-tools.json` and the setup helper pin the new hash. Direct conversion of all three supported WMA tracks to Ogg Vorbis succeeded. A fresh `content-prepare` run returned manifest SHA-256 `f5d9d1c0ca0d91991d5f900441a435c35dd2049105268ca4a11183118f02a1e9`. The FNA content probe loaded 96 XNBs with zero failures, including all three music tracks at 302.091, 817.992, and 907.713 seconds. A direct phone-only install through the packaged setup helper returned `INSTALL_COMMITTED`, and verification of its destination returned `INSTALL_VERIFIED`.

`installer/ffmpeg/package-source.py` verifies the source archive hashes and converter hash, checks the reported license and build flags, then creates the companion `installer/out/FFmpeg-8.1.1-source.zip`. The ZIP contains complete FFmpeg, libogg, and libvorbis source archives plus the Dockerfile and build script. Its SHA-256 is `2a1a7781fb571b2485afaa40f8492e4c5ce381462e2e2d39a316018b6e990ea3` (18,682,792 bytes). Two consecutive package runs produced the same hash. The setup payload includes full FFmpeg LGPL 2.1, FFmpeg license explanation, exact libogg/libvorbis license texts, and a notice naming the matching source ZIP.

The rebuilt `installer/out/ZombiesPort-Setup.exe` SHA-256 is `d86d3b82c9ce69d1cf50573d6b68e0e693820951994fcc12f142e9c4c8685ab2` (189,994,957 bytes). `python installer/audit-release.py --xap 'game/Z0MB1ES (on teh ph0ne) v1.0.0.0.xap'` reported `source_files=183 payload_files=232`, five negative controls passed, and `AUDIT_CLEAN`. The audit now requires the matching source ZIP and full installed FFmpeg notices, compares those notices with the source archives, verifies the ZIP's archive and build-script contents, and rejects a converter with a libwinpthread dependency. It does not establish that a future release page actually offers both files.

For release, offer **both** `ZombiesPort-Setup.exe` and `FFmpeg-8.1.1-source.zip` at the same download location and keep them available together. Players run only setup. No public release was made here. The clean-account interactive wizard and hands-on game checks from P4, plus a final review of the other bundled dependency notices, remain open before publication.
