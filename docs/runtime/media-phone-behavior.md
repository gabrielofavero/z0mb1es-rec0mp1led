# Media and phone-only behavior (Prompt 11)

The supported original DLL calls `Music.LoadSong`, `Music.Start`, `Music.Update`, `Music.Stop`, `Music.Pause`, and `Music.Resume` around its `MediaPlayer` operations. `BaseTimeMgr.Pause` and `UnPause` call the original music methods. `Sound.Init` loads 19 `sfx/fx/` keys into a dictionary; `Sound.Play`, `PlayExplode`, `PlaySword`, and `PlayHit` call `SoundEffect.Play`. The content preparer supplies local Ogg companions for the original three WMA songs; all other sound XNBs are unchanged. Media playback follows the original calls through FNA, with the completion adaptation below.

Endless selects only `sfx/music/endless` (about 302 seconds). The original `Music.Update(2)` resets its play counter when playback stops, then starts the same song on the following update. It does not alternate tracks. Normal Zombies and Time Viking keep their original finite-song behavior.

The local Vorbis decoder audit found that `endless.ogg` declares 13,322,194 samples but supplies 13,320,192 decoded samples. The bundled FAudio implementation marks the final buffer only when the decoded count reaches the declared length, so it can exhaust its audio while continuing to report `Playing`. A 0.25-second local clip reproduced the missing completion and absent replay. The guarded `Music.Update` state read now calls `Port.Hooks.MusicPlayback.GetState(Song)`: if playback is still `Playing` 250 ms beyond the loaded song's duration, it stops the player and lets the original mode logic handle completion. FNA's playback position excludes paused time and resets on Stop. Paused/stopped states and unknown durations bypass the fallback. The loaded song is passed explicitly because FNA's queue clone initially has a zero duration.

The regression check exercises three Endless replays, a pause longer than the clip, resume, explicit stop, both finite modes, and disabled BGM through the prepared game's actual music methods. After building, create a short local clip and run it on macOS (use the corresponding native directory and loader path on other hosts):

```sh
private/macos-inputs/ffmpeg -i private/run/current/Content/sfx/music/endless.ogg -t 0.25 -c:a libvorbis -y private/music-investigation/short.ogg
DYLD_LIBRARY_PATH="$PWD/out/deps/native/osx-arm64" dotnet run --project tests/IosGame.Checks -c Release -- --music-playback-check private/run/current/ZombiesWP7.dll private/music-investigation/short.ogg out/deps/native/osx-arm64
```

The clip and diagnostics remain in ignored `private/`; create `private/music-investigation/` before running the conversion. This accelerated check does not establish audible quality or a full-length device run.

The [audio portability audit](audio-portability.md) records the embedded PCM formats, Ogg Vorbis headers, and non-Windows preparation requirements.

`CustomMgr.Init` originally enumerates phone media sources, then traverses a `MediaLibrary` only if any source exists. The guarded call target returns an empty source list with an informational trace, so the game does not attempt phone photo-library access on desktop. Setup lets the player choose a picture folder beside the installation and save folders. The selected folder and its subfolders supply up to 256 readable PNG or JPEG pictures as aspect-preserving previews up to 400 pixels in **Edit Monsters**. The path is passed by the launcher and reused by shortcuts on later starts. Invalid images are skipped; an empty folder leaves the creator without pictures. The creator's preview and controls are centered on wide desktop scenes. Use the arrows to browse, click the photo or USE to add it to the random monster pool, then click the enabled photo to move its mask. Drag the size slider with the mouse, or use the right stick or shoulder buttons on a controller. Click USE again to remove it. The circular mask stays inside the photo at every slider position, even for portrait images. Image loading and saved custom sprite reapplication happen on the game thread because graphics operations during background startup can race the renderer. `AccelMgr` subscribes to accelerometer readings and starts the sensor; the bridge reports no connected sensor and emits no readings. `Vibration.SetVibration` calls `VibrateController.Start`; the bridge sends timed rumble to connected, supported controllers on every host. If no controller accepts rumble, both iOS hosts use Core Haptics on devices that support it. The saved vibration setting gates feedback, and disabling it, leaving the application, or shutting down cancels active effects. Unsupported hardware remains a nonblocking fallback. Older iPhones without Core Haptics use the system’s fixed vibration pulse, whose duration and cancellation are controlled by iOS. Future mobile hosts can register their device motor through `GameVibration.DeviceOutput`.

The original upsell menus call `Guide.ShowMarketplace`; one dialog result path creates `MarketplaceDetailTask` and calls `Show`. Both now report that the phone marketplace is unavailable and show a Windows notice when interactive. They do not open a store, grant a license, or claim a purchase. The desktop full-game trial policy makes ordinary upsell entry unlikely; a player-facing click check has not been completed. `Guide.BeginShowMessageBox`/`EndShowMessageBox` now uses a Windows choice dialog when interactive; on other platforms or when dialogs are suppressed, it returns a dismissed result so the game can continue.

The main menu's Back action calls `Guide.BeginShowMessageBox` for its phone quit confirmation. This was the reported `BridgeApiUnavailableException` during the 2560×1080 run. That exact quit request now completes as Quit without opening a Windows dialog. The game's own in-game Quit and End Game confirmation menus remain available. Other guide messages use the desktop choice implementation; the bridge check verifies asynchronous result, callback, state, and dismissed result when dialogs are suppressed.

The prepared content probe at `private/content-prepared/net10-a` passed all 96 XNB loads, including 19 sound effects and three songs. With `--exercise-audio`, it confirmed `MediaPlayer.GameHasControl` is true, started and stopped each effect, played two instances of one effect simultaneously, then checked play, pause, resume, and stop on each song. It exited while the final song was playing; the process ended with code 0 and no media exception. A 300-frame run of the original game loop with the updated bridge reached the animated menu and saved cleanly. These checks establish FNA playback and the menu path on this machine. They do not establish audible quality, exact original-game mode transitions, device rumble, or player-facing marketplace notice behavior; mode play remains Prompt 12 work.
