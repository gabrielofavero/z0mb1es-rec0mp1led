# Desktop input progress (Prompt 9)

The original DLL sets `Game1.VIEWPORT` to 600×360 and applies a 600×360 backbuffer. `TouchMgr.Update` reads `GamePad.GetState`, one `TouchPanel.GetState`, and at most one queued gesture each update. Its touch logic uses pressed/moved/released states and separates left and right controls at half the original viewport width. `Viking_x86.main.MainMenu.Update` accepts a touch click in the central x region (100 to the screen width minus 100). These are IL-derived facts; no original phone runtime was available.

The [guarded call adaptation](../../patches/desktop-input.md) supplies contact and gesture values without changing `TouchMgr` or menu decision code. On menus, a left mouse click creates a contact and tap at the pointer. During play, holding either mouse button creates a right-stick contact pointing from the player to the pointer. The player screen position comes from the original `ScrollMan.GetScreenLoc` or `VScroll.GetScreenLoc` method. The original top-right pause hotspot remains clickable. WASD and the left stick create a movement contact; arrow keys and the right stick create an aim contact. A virtual stick first presses its center, then moves to the requested offset for the game's relative-control setting. Enter and controller A tap the selected menu option. Escape and Backspace send one original Back event per press; controller Start sends Back during play, while Select/Back remains a menu cancel key. Ctrl+Q exits the diagnostic host. The launcher makes the mouse cursor visible and allows window resizing. Pointer coordinates are scaled uniformly from the window client area to the original backbuffer; margins outside the resulting 5:3 viewport are ignored.

`Input.Checks` passes coordinate checks at native size, 2× size, and a letterboxed 1000×500 window, including rejection of margin coordinates; it also checks aim vectors. The patched DLL passes `--check-load` for 177 types and 818 JIT-prepared methods. A focused keyboard run observed the original main-menu state 1, then state 2 after Enter, movement from held W, a click, a Back event, and return to state 1. A later hidden test helper kept the game focused and reached playing state 3; a playfield mouse hold produced `mouseSamples=66` and `aimSeen=True`. Escape produced `backSeen=True` and `pauseActive=True` without closing the host, and Enter cleared the pause menu while state 3 continued. The run ended at 1,500 frames with `pauseSeen=True`, `hostQuit=False`, `timedOut=False`, and exit code 0.

Earlier automated Win32 injection from a visible PowerShell process lost FNA window focus, so those runs were inconclusive. A hidden helper avoided the focus loss and supplied the observed mouse and Escape results above. SDL enumerated an Xbox One controller, but controller Start/Select/A/sticks have not been exercised. A manual focused-window pass is still needed for visible mouse direction, controller controls, every mode, and live resize before Prompt 9's full gate can pass.

The bridge now reports `IsTrialMode=false` and `SimulateTrialMode=false` as an explicit offline desktop policy for the user-supplied supported XAP. `TrialMgr.trial` was observed false in the running menu and gameplay. This does not verify an original phone license. The game still writes its original isolated-storage save under Windows AppData during startup; Prompt 10 must replace this with a stable desktop save policy. The diagnostic timeout applies only to frame-limited runs; interactive sessions can continue until Ctrl+Q, the game's own exit, or window close.

## Controller enhancement

The D-pad and left stick move a visible focus across each active `MenuLevel` using item positions, including pause, settings, confirmation, and option screens. Up and down follow the screen layout and wrap; left and right cycle through items in visual reading order. Keyboard arrows and WASD use the same navigation. On the main carousel, left and right slide the scene selection to the next option in 0.2 seconds with cubic easing. Touch swipes and pointer arrow clicks still use the original inertia path. A or Enter finishes an in-progress slide before activating the selected item through the original tap path. B or Escape sends the original Back action to cancel the active menu or back out of a mode lobby. Start still pauses during play. Directional virtual touches are limited to gameplay so menu stick movement does not scroll or swipe accidentally.

The guarded player-settings constructor now initializes `showTouchPads` to false. Existing saved preferences are read as before. `Input.Checks` covers spatial menu navigation, horizontal cycling, direction mapping, and carousel easing for D-pad, stick, arrows, and WASD. A prepared-assembly check confirmed the carousel hook moves `MainMenu.sceneMgr.video.time` through a midpoint and lands on the next option in both directions; it also finishes a slide before confirmation. The patched assembly passed the 177-type, 818-method load check. A fresh-profile menu probe rendered all 17 original levels and captured Settings with Show Touchpads unchecked. Physical controller button presses still need a focused-window play pass; the automated menu probe activates levels directly and does not exercise those button edges.
