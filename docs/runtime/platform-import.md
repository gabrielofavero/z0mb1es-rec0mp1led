# Persistent platform import contract

`PersistentAssetStore` in `Port.Prepare` owns the app-data asset transaction. A host supplies an asset directory and a separate save directory, the shared `GamePreparationPipeline` through a preparation delegate, and an `IOptionalArtImporter`. The active layout is `assets/current/game`, `assets/current/content`, `assets/current/phone-original`, and, when selected, `assets/current/optional-art`. `asset-manifest.json` lists every imported file with size and SHA-256. It stores the supported phone version and fingerprint, but no source path. The original phone extraction stays in private asset data so optional art can be added later without asking for the original XAP. The app package, asset data, and saves can live in separate locations.

`Preview` verifies the selected XAP and optional source fingerprints before creating staging files. It reports phone and art versions, source bytes, an intentionally conservative peak-space estimate, and available space. `Import` copies or prepares into a sibling staging directory, verifies the prepared DLL and content manifests, checks all staged files, and moves the previous active set aside before activating the new one. A failed or canceled stage leaves `current` intact. If activation is interrupted after moving `current` aside, `TryOpen` restores `previous`. A valid backup is also restored if the new active set fails verification. Once activation verifies, the old set is removed. The transaction never writes to the save directory.

Phone-only import is complete original art. Normal art accepts exactly one supported I MAED Steam or 360 source; Time Viking accepts its supported 360 source independently. `PinnedOptionalArtSource` uses the exact source hashes from `config/supported-steam-versions.json` and `config/supported-360-versions.json`. `ExternalOptionalArtImporter` calls a host-supplied art tool, decoder, and FNA assembly, then probes and composes Endless. Replacing the base retains verified optional art; replacing one optional source retains the other. The source files can be deleted after commit.

`AssetImportFlow` in `Port.Host` drives `IGameFilePicker` and `IAssetImportView` for first import, repair, and Settings Reimport. The view chooses which sources to replace, shows the preview and progress, and keeps the importer open after a failed or incomplete attempt. `AssetSessionCoordinator` verifies on ordinary starts and skips the picker when valid. A host game-session callback returns `true` for Reimport **after disposing the game**; the coordinator then runs the importer and starts a fresh session. Cancellation or failure relaunches the existing set. `Z0MB1ES --run-managed` emits exit code 10 when the Settings action is selected, so a platform host can run the game in a separate process and get a fresh assembly after import. The existing Windows `--run` path continues to use Setup for reimport.

The Linux x64 host now supplies Zenity file/photo pickers and progress, XDG app-data paths, packaged preparation/art tools, and game-process wiring. A headless WSL check imported the supported XAP into a persistent asset set, but the real GTK UI and graphical package installation remain untested because this WSL environment has no display. The current Windows setup remains the only visually accepted player importer. The transaction test harness uses real prepared phone manifests and injected optional-art output; it checks transaction behavior, not visual art quality or native UI.
