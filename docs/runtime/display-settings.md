# Desktop display settings

The original phone game renders at 600×360. The prepared DLL's guarded `Game1.Draw` hook now grows the logical scene to the display's aspect ratio, keeping at least 600×360 visible. It updates `Game1.VIEWPORT` and both gameplay camera screen sizes with that scene size, so wider or taller displays reveal more world. For example, 2560×1080 uses an 854×360 scene, while 800×600 uses 600×450. The full scene uses point sampling and one uniform scale on both axes; integer scene rounding can leave a subpixel black edge. Mouse and virtual controls use the same presentation scale and expanded coordinates. Original menu rows are offset to stay centered as the scene grows, with their input positions following the same offset. This does not replace the original art or add texture detail.

The original Settings menu now shows SFX, BGM, `DISPLAY`, and `T0UCH` in that order. `T0UCH` holds the original Vibration, Relative Controls, and Show Touchpads switches; their saved states and original click handlers remain in use. All subpages are rendered by the game's own `MenuLevel` and `MenuItem` code, using its original font and layout. `BACK`, Escape, or controller B returns to the parent page.

The Display page shows Mode, Preset, VSync, Custom Resolution, and Back. It cycles Windowed, Borderless, and Fullscreen modes and resolution presets up to 3840×2160. The preset cycle includes only sizes that fit within the desktop display dimensions detected at startup; an active custom or larger saved size appears as `PRES3T: CUST0M`. The `VSYNC` row switches vertical synchronization on or off immediately. Custom Resolution opens a separate page with Width, Height, Apply Custom, and Back. Width and Height accept typed digits after selection; Apply Custom applies values from 600–3840 pixels wide and 360–2160 pixels high. Borderless uses the detected desktop display size; its saved custom size is restored when returning to Windowed or Fullscreen. Mode, preset, and VSync changes apply immediately; custom dimensions apply when selected.

Display preferences, including VSync, are saved as `display.json` beside the desktop save in the user's local application data directory. An isolated `--save-dir` redirects both. Existing files without a VSync value default to on. Invalid saved dimensions are ignored. Unsupported display changes are reported in the menu's info text.

The original `Game1.Draw`, `Settings.Click`, and `Settings.Cancel` method bodies are SHA-256 guarded before hooking. The hooks assembly hash is also pinned for Debug and Release builds. A release build and prepared assembly rendered Touch, Display, and Custom Resolution pages, checked the category order and parent navigation, toggled VSync in both directions, cycled only 600×360, 1280×720, 1920×1080, and 2560×1080 on a 2560×1080 desktop, and applied a custom resolution. Separate staged runs rendered at 3440×1440 and 3840×2160 in Windowed mode, at a 2560×1080 desktop size in Borderless mode, and at 1280×720 in Fullscreen mode. The automated probe activates menu actions directly; physical key presses and mouse clicks still need a focused-window play pass.

The expanded viewport passed a 2560×1080 normal-mode and Viking-mode play, pause, resume, and return probe. Both captured gameplay frames show world content across the full display width. Window resizing and live settings changes recreate the scene target at the new aspect ratio; a focused-window play pass is still useful for physical pointer input at those sizes.

The centered-menu build also passed the complete 17-level menu probe in 2560×1080 Fullscreen mode. Its captured Settings and Display pages place the original menu text in the middle of the expanded scene. The probe includes live resolution and mode changes, category navigation, VSync, and custom resolution entry.
