# Desktop display settings

The original phone game uses 600×360 coordinates. The prepared DLL's guarded `Game1.Draw` hook grows the logical scene to the selected resolution's aspect ratio, keeping at least 600×360 visible. It updates `Game1.VIEWPORT` and both gameplay camera screen sizes with that scene size, so wider or taller selections reveal more world. For example, 2560×1080 uses 854×360 logical coordinates, while 800×600 uses 600×450. The render target uses the selected resolution even in Borderless and Fullscreen modes. Guarded `SpriteBatch.Begin` calls apply a uniform logical-to-physical transform while that target is bound, so imported high-resolution art retains its detail. Offscreen texture baking keeps its own coordinates. The scene is centered into the output backbuffer with black bars when its aspect ratio differs. Mouse and virtual controls use the same presentation scale and expanded coordinates. Original menu rows are offset to stay centered as the scene grows, with their input positions following the same offset.

The Settings menu shows `GRAPH1CS`, `AUD10`, and `GAMEPLAY`. Gameplay shows Player Name as a static label and the current name as the single selectable editing row, then Input. Its rows use alternating horizontal offsets like the other Settings pages. Player Name accepts up to 16 ASCII letters, digits, spaces, hyphens, underscores, or apostrophes; Enter or controller A saves, while Escape or controller B cancels. FNA's SDL text input requests a platform on-screen keyboard where supported. Input holds the original Vibration, Relative Controls, and Show Touchpads switches; their saved states and original click handlers remain in use. Graphics contains Mode, Resolution, VSync, Reduce Flashing, and Assets. Resolution cycles its choices on that page. Assets contains the art choices for I MAED, Time Viking, and Endless. Audio retains the original SFX and BGM switches. All subpages are rendered by the game's own `MenuLevel` and `MenuItem` code, using its original font and layout. `BACK`, Escape, or controller B returns to the parent page.

Graphics cycles Windowed, Borderless, and Fullscreen modes. The Resolution row cycles Auto and presets up to 3840×2160. Auto is the default and uses the desktop display resolution detected at startup, with a minimum render size of 600×360. The preset cycle includes only sizes that fit within that display. The Graphics `VSYNC` row switches vertical synchronization on or off immediately. Borderless and Fullscreen keep a desktop-sized output backbuffer while the selected resolution controls scene detail and aspect ratio; Windowed uses the selected size for its window. Mode, preset, and VSync changes apply immediately. Older display files without an Auto value migrate to Auto.

Display preferences, including VSync and Reduce Flashing, are saved as `display.json` beside the desktop save in the user's local application data directory. An isolated `--save-dir` redirects both. Existing files without a VSync value default to on. Invalid saved dimensions are ignored. Unsupported display changes are reported in the menu's info text. On a fresh Windows setup, the installer can create this file with Reduce Flashing on before the first launch; it never replaces an existing display file.

The original `Game1.Draw`, `Settings.Click`, and `Settings.Cancel` method bodies are SHA-256 guarded before hooking. The hooks assembly hash is also pinned for Debug and Release builds. Earlier staged runs covered custom resolution; the current menu probe covers Auto, the preset cycle, and a Borderless preset change. The automated probe activates menu actions directly; physical key presses and mouse clicks still need a focused-window play pass.

The expanded viewport passed a 2560×1080 normal-mode and Viking-mode play, pause, resume, and return probe. Both captured gameplay frames show world content across the full display width. Window resizing and live settings changes recreate the scene target at the new aspect ratio; a focused-window play pass is still useful for physical pointer input at those sizes.

The centered-menu build also passed the complete 17-level menu probe in 2560×1080 Fullscreen mode. Its captured Settings and Display pages place the original menu text in the middle of the expanded scene. The probe includes live resolution and mode changes, category navigation, and VSync.

With a 1920×1080 preset on the 2560×1080 test desktop, the new Fullscreen output kept a 2560×1080 backbuffer and rendered into the center 1920 pixels. The captured frame's outer 320-pixel strips were entirely black on both sides. The updated 17-level menu probe passed in Windowed and Fullscreen modes; its Borderless check changed the selected render size while retaining the desktop backbuffer.
