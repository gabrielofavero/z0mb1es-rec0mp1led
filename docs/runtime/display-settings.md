# Desktop display settings

The original phone game renders at 600×360. The prepared DLL's guarded `Game1.Draw` hook draws that scene into a 600×360 render target, then scales it to the current backbuffer with centered black bars. Mouse input uses the inverse transform. This keeps the original menu and gameplay coordinates intact at 4:3, 16:9, and ultrawide display sizes. Display resolution changes presentation size; it does not replace the original game art or reveal more of the game world.

The original Settings menu now shows SFX, BGM, `T0UCH`, and `DISPLAY`. `T0UCH` holds the original Vibration, Relative Controls, and Show Touchpads switches; their saved states and original click handlers remain in use. Both subpages are rendered by the game's own `MenuLevel` and `MenuItem` code, using its original font and layout. `BACK`, Escape, or controller B returns to the Settings page.

The Display page cycles Windowed, Borderless, and Fullscreen modes and resolution presets up to 3840×2160. The preset cycle includes only sizes that fit within the desktop display dimensions detected at startup; an active custom or larger saved size appears as `PRES3T: CUST0M`. The `VSYNC` row switches vertical synchronization on or off immediately. Width and Height rows accept typed digits after selection; selecting `APPLY CUST0M` applies values from 600–3840 pixels wide and 360–2160 pixels high. Borderless uses the detected desktop display size; its saved custom size is restored when returning to Windowed or Fullscreen. Mode, preset, and VSync changes apply immediately; custom dimensions apply when selected.

Display preferences, including VSync, are saved as `display.json` beside the desktop save in the user's local application data directory. An isolated `--save-dir` redirects both. Existing files without a VSync value default to on. Invalid saved dimensions are ignored. Unsupported display changes are reported in the menu's info text.

The original `Game1.Draw`, `Settings.Click`, and `Settings.Cancel` method bodies are SHA-256 guarded before hooking. The hooks assembly hash is also pinned for Debug and Release builds. A release build and prepared assembly rendered both Touch and Display pages, toggled VSync in both directions, cycled only 600×360, 1280×720, 1920×1080, and 2560×1080 on a 2560×1080 desktop, and applied a live resize from 600×360 to 1280×720 and back. Separate staged runs rendered at 3440×1440 and 3840×2160 in Windowed mode, at a 2560×1080 desktop size in Borderless mode, and at 1280×720 in Fullscreen mode. The automated probe activates menu actions directly; physical key presses and mouse clicks still need a focused-window play pass.
