# Custom image asset packs

**Status:** Planned. Extend the [optional asset swap](../in-progress/2026-11-07-asset-swap.md) implementation after its current release gates. The supported phone XAP remains required and supplies the fallback for every image. Steam and Xbox 360 imports remain optional. The export tool is developer-only; players import an edited pack through setup.

## Player and author contract

- A developer command exports a complete, editable PNG workspace. Include one stable `working/` PNG path for **every image-bearing asset** in the supported phone content, including game art, shared menus, achievements, touch/UI art, scene images, and font atlas pages. Export the decoded phone originals under `original/` as references. Decode every image from each supplied, supported Steam/360 source under `sources/<source-id>/`, including source-only images, and list any source image that cannot be decoded as an export failure. Non-image XNB data, video, audio, and runtime-created/user-photo textures are outside this image pack.
- Fill each working image with the best verified high-resolution artwork available for its phone regions. Reuse the existing per-element Steam/360 mappings, crop/remap/repack differing atlases, and fill unmatched regions from the phone original at the working scale. The manifest labels the provenance and actual source resolution of each region so an upscaled phone fallback is never described as new detail. Source-only art without an approved phone mapping is a reference, not an automatic replacement.
- Authors edit `working/` PNGs and may omit any number of files from the submitted pack. Setup imports only files that are present. For each visual slot at runtime, resolve **custom → verified imported high-resolution art → phone original**. A partial custom pack must never blank or corrupt an unrelated image or region.
- Each replacement must have the phone asset's exact aspect ratio and a **single positive integer scale factor** on both axes: `width = baseWidth × N` and `height = baseHeight × N`, where `N = 1, 2, 3, ...`. Reject nonuniform scales, fractional scales, crops, and extra canvas padding. Keep phone atlas coordinates, logical size, origins, hit boxes, and animation timing unchanged. A 2× atlas must place every sprite at exactly 2× its phone coordinates; a differently arranged atlas needs an explicit authored mapping before it can be imported.
- Add a **CUSTOM** category to **HELP AND OPTIONS → SETTINGS → ASSETS**. Show pack name, coverage by game/shared UI, validity, and a repair instruction. The existing I MAED, TIME VIKING, and ENDLESS rows offer `AUTO`, `ORIGINAL`, and available explicit sources. `AUTO` uses the priority above per image/region; `ORIGINAL` forces phone art. Migrate the existing `original` preference to `ORIGINAL` and `imported` to the corresponding explicit imported source so an update does not silently change a deliberate choice. A fresh install defaults to `AUTO`. A corrupt or removed custom pack falls through to the imported source or Original without deleting the saved preference. Changes take effect safely when textures are reloaded.
- Setup offers **Import custom assets** with a folder picker, validation summary, and add/replace/remove/repair behavior. A phone-only install needs no custom pack. Custom artwork, source packages, and exported workspaces are never bundled in the public installer or committed to Git.

## Format and ownership

1. Create a versioned `asset-catalog.json` from the pinned XAP and existing inventory/mapping evidence. Give every phone image a canonical ID, normalized phone content path, object type, base width/height, decoded hash, eligible game modes, and optional atlas/frame regions. Include shared and non-gameplay images that the current draw-route inventory does not cover. Record the supported source-image inventory and explicit mappings separately. Fail the export if any image-bearing XAP object has no catalog row or no decoded PNG.
2. Use `working/<phone-relative-path>.png` as the stable replacement key. For image objects embedded in another content type, such as SpriteFont pages, assign deterministic page suffixes and preserve their existing glyph/layout metadata. The custom pack manifest contains catalog version/hash, optional display name, file paths, phone base dimensions, image dimensions, scale, and SHA-256. A file omitted from the pack means fallback, not deletion. Treat unknown paths and duplicate IDs as errors so typos cannot appear to import successfully.
3. Keep `original/` and `sources/` as developer references outside the player pack. The pack template may include a compact manifest and `working/` tree; an author can delete unchanged `working/` files before import. Document alpha/color expectations, PNG encoding, atlas guides, and that generated source artwork may be copyrighted player-owned material. Never ship extracted pixels in the repository or setup payload.

## Implementation sequence

### 1. Complete export and editing template

- Add a developer-only command, for example `dev.ps1 export-assets`, that takes the pinned phone XAP and optional supported Steam/360 inputs. Reuse `Port.Content`, the existing XNB decoder, source fingerprint checks, and asset-swap mappings. Decode to lossless RGBA PNG without silently dropping mip or palette/alpha information; record any conversion limits. Export every supported source image even when it has no phone mapping, and generate the complete `working/` tree from phone images plus approved high-resolution regions.
- Choose one uniform working scale per phone image. Prefer the highest verified integer scale available for mapped regions; for mixed atlases, scale the full phone canvas and place source crops at exact phone-relative coordinates. Label original-derived pixels separately. Reject mapping geometry that cannot be placed without overlap or clipping. Generate a coverage report: phone image count, exported image count, mapped regions, original-derived regions, source-only images, and failures. Zero missing phone images is a hard gate.
- Add a small README to the exported workspace with path examples, atlas guides, and the command for local preflight validation. Keep all generated pixels in ignored local output.

### 2. Validate and install custom packs

- Extend the setup helper and Inno wizard with a custom folder selection independent of Steam/360 selection. Validate the catalog version and every submitted PNG before mutation: safe relative path, no links/path escape, matching PNG signature and actual decoded dimensions, uniform integer scale relative to the **phone** base dimensions, bounded size/memory, readable RGBA data, duplicate/case-collision checks, and a hash for each accepted file. Reject the entire candidate with file-specific errors if any submitted image is invalid; report omissions as fallback coverage.
- Stage a versioned custom generation under `current/optional-art/custom/`, beside existing source generations. Store a manifest of accepted files, hashes, base sizes, scales, catalog fingerprint, and coverage. Verify the staged generation and the final install manifest before atomic commit. Keep the previous generation and saves on failed import, interrupted setup, or rollback. Support later keep, replace, repair, and remove without needing to reimport other art sources.
- Keep a developer `validate-custom-pack` command that uses the same validator as setup. Make the complete export template pass validation, and make a sparse pack with just one PNG pass. Ensure the release payload contains the validator but no exported images.

### 3. Resolve and render at the requested priority

- Extend `AssetDraw` and any image loads outside its current 170 patched draw calls to resolve a custom full-image route before the existing per-element high-resolution route. For a custom atlas, multiply source rectangles by its integer scale and divide origins or adjust draw scale so the logical phone result is unchanged. Handle `source == null`, destination rectangles, SpriteFont pages, menu/achievement/UI drawing, mode-shared textures, disposal/reload, and filtering/edge bleed. If full-image routing cannot safely cover a draw path, add an explicit guarded hook and catalog entry rather than leaving an apparently importable image unused.
- Resolve each mode independently. A missing custom image or uncovered approved region uses the installed high-resolution route when available, then the phone texture. Keep the current Endless source order **inside** the high-resolution tier: I MAED 360, Steam I MAED, Time Viking 360, Original. Custom sits above that tier. A damaged custom generation is unavailable as a whole until repaired; a valid sparse generation falls through per missing file. Verify generation hashes at launch/selection, and preserve the last saved choice when a source is unavailable.
- Extend the ASSETS Settings UI and `assets.json` schema with the CUSTOM category and the per-mode `AUTO`/explicit selection model. Show imported/custom coverage and an actionable setup repair message; preserve menu navigation and saves. Confirm whether changing a choice requires ending the current game session or can safely invalidate cached textures, then implement and test that behavior explicitly.

### 4. Prove completeness and player behavior

- Export the pinned XAP alone, then with each supported Steam/360 combination. Compare the catalog against the actual decoded content inventory: every phone image has a PNG and stable path, and every supplied source image is exported or fails loudly. Check representative repacks (`grass`, moon stages, zombie sprites), shared UI, achievements, SpriteFont pages, and mixed Endless art against references.
- Exercise valid 1×/2×/3× packs, one-file and incomplete packs, changed aspect ratio, noninteger/nonuniform scale, corrupt PNG, unknown path, duplicate case, oversized image, linked path, and wrong catalog version. Confirm invalid packs leave the prior install intact and that removal or corruption triggers the stated fallback.
- Run each game and shared screens with `AUTO`, `ORIGINAL`, and explicit imported choices at native/widescreen/ultrawide output. Verify frame/crop alignment, alpha edges, font rendering, menu/input geometry, animation, and fallback when only some custom images exist. Test restart, update, repair, reinstall, rollback, and unchanged save hashes. Extend installer allow-list/audit so no extracted or custom pixels enter setup. Record exact inputs, commands, counts, failures, and visual results in the implementation log.

**Done when:** The developer export has every supported image file in readable PNG form, the player can import a valid partial custom pack through setup, Settings exposes CUSTOM and the selection choices, and each image resolves custom → high-resolution import → phone original without changing game behavior or requiring optional sources.
