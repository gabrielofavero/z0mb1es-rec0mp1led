# Linux x64 packages (Prompt 2)

The locally built `.deb` and `.rpm` install only authored code, the .NET runtime, FNA and its native dependencies, the optional-art helper, and the WMA converter. No phone DLL, XAP, XNB, prepared art, or generated game content belongs in either package. Package scripts only place files under `/opt` and `/usr/share`; they do not ask for a XAP. The desktop entry starts `--linux`, which opens the first-launch GTK picker through Zenity. The package manager installs Zenity as a normal package dependency.

On first launch, choose the exact supported phone XAP. Supported I MAED Steam/360 and Time Viking 360 art sources are optional; the XAP alone supplies complete original art. The importer shows source version, selected-package size, estimated peak disk use, and available space before preparing into app data. A canceled or failed import can be retried next launch. Later use **Settings → Graphics → Assets → Reimport** to replace or add sources. Imported files are copied into `$XDG_DATA_HOME/z0mb1es-rec0mp1led` (default `~/.local/share/z0mb1es-rec0mp1led`); `assets`, `saves`, and `pictures` are separate folders. The original packages can be deleted after a successful import. Press **P** in the creator's picture mapper to select PNG/JPEG photos through the system dialog; selected files are copied to `pictures` for later sessions. Uninstalling a package leaves these user files unless the user removes them separately.

## Reproducible build inputs

- .NET SDK `10.0.302`; self-contained runtime packs `10.0.10` and their SHA-256 values are in `config/linux-packaging.json`.
- FNA managed `26.11`; the `2026-11-06` FNA native daily archive supplies SDL3, FNA3D, FAudio, and Theorafile. The archive and individual library hashes are pinned in `config/linux-packaging.json`.
- FFmpeg `8.1.1` at source revision `239f2c733d`, libogg `1.3.6`, and libvorbis `1.3.7`. Build with `installer/linux/build-ffmpeg.sh` from the matching source ZIP; the resulting Linux converter hash is `7895c3b0687e340f7bee2d2ac5d7049b7a91eec003b042db1263555131c7c562`. Its `-L` output is LGPL 2.1 or later. Run `python installer/linux/package-source.py` and ship `FFmpeg-8.1.1-linux-source.zip` next to both packages.
- Python `3.8.10`, the exact packages in `installer/linux/requirements-build.txt`, and the sibling `xnb_parse` checkout build the self-contained optional-art helper. Build it on an Ubuntu 20.04 x64 environment with `PYTHON=/path/to/venv/bin/python3 sh installer/linux/build-art.sh`.
- nFPM `2.48.0` builds both package formats from `installer/linux/nfpm.yaml`. Its archive SHA-256 is pinned in `config/linux-packaging.json`.

The `out/deps/cache` runtime packs, FNA native archive, FFmpeg source ZIP, Linux converter, frozen art helper, and nFPM binary are local build inputs under ignored directories. After those inputs are ready, run `python3 installer/linux/bootstrap-native.py` and `installer/linux/build.ps1` from PowerShell on the development machine; the latter cross-publishes Linux ELF binaries and invokes `installer/linux/package.sh` in WSL. On a Linux developer machine, use the same `dotnet restore -r linux-x64 --source out/deps/cache` and `dotnet publish -c Release -r linux-x64 --self-contained true` commands for `Port.Launcher`, `inspect_assembly`, `abi_check`, and `decode_360_xnb`, placing outputs in `private/linux-publish/{game,inspect,abi,decode}`. Publish the ABI checker as a directory, not a single file, because it inspects the runtime assembly catalog. The inspector and decoder may be single files. Then run `sh installer/linux/package.sh`. Outputs are in `out/linux/packages`.

## Current acceptance

The packages and converter have been built locally, and the Linux x64 host loaded the prepared game DLL with all 177 types and 818 JIT-prepared methods. The headless import transaction and package audits are recorded in the implementation log. The WSL environment has no graphical session, Zenity, RPM installer, or native GPU/audio/controller test hardware. Graphical package-manager installation, visible picker/progress, desktop-entry launch, full gameplay, creator photo UI, and update preservation still need a Linux desktop pass before Prompt 2 acceptance can be closed. The package files are local test artifacts, not a published release.
