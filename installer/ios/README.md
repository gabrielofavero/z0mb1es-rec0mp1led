## Import and play

1. Install over the current app with the same signing identity/options and launch once. This creates **Files → On My iPhone → Z0MB1ES → Imports** and its instructions file.
2. Copy the supported phone XAP directly into **Imports** using Files. Optionally copy an I MAED Steam ZIP/folder or Xbox 360 LIVE package and a Time Viking Xbox 360 LIVE package into the same folder. Finish copying/downloading before scanning. A Steam ZIP must contain one `Z0MB1ES.exe` with its matching `Content` folder. The executable is checked for identity and never executed.
3. Return to the app, acknowledge the flashing warning if shown, and tap **Rescan**. Swipe to reach all controls. Tap each source row to cycle through verified choices. A first import selects the verified XAP. Available artwork is selected automatically, preferring I MAED 360 over Steam when both are present. Tap a source row to choose Original/Keep instead; Rescan preserves that explicit choice.
4. Tap **Import and play**. The shared in-process pipeline validates, prepares game code and converts graphics/music/art on a worker while FNA draws progress. Cancel or background the app to request cancellation. Invalid, incomplete, linked or changed sources do not replace the active installation. Source packages are retained in Imports; the app never deletes them.

On success, setup exits and disposes its graphics/window before the original `ZombiesWP7.Game1` starts. Later launches verify persistent data and start the game without source files or setup, once the warning is acknowledged. Saves and preferences remain separate from replaceable content. A game-start repair requires closing the app from the app switcher and reopening after import, because loaded game assemblies cannot be safely replaced in that process.

**Reimport assets** opens setup after pausing, saving and disposing the current game. Artwork-only imports reuse the installed phone content. Selecting an artwork source also selects Enhanced for that game and Endless, even if an older preference said Original; unselected modes keep their existing preference. Completed reimport clears its request and shows **Reopen to play**. Failed/cancelled imports retain the active assets and saves. Backgrounding requests cancellation; a fresh launch cleans interrupted transaction scratch directories.

Photos are selected using iOS PHPicker, with orientation-aware ImageIO thumbnails converted to sRGB (maximum 400 pixels, 32 selections at a time, 256 stored pictures). App-private PNG copies retain stable names; texture upload/reapplication runs on the game update thread. No full-library permission or external photo paths are required. HEIC/JPEG/PNG support follows the OS decoder. Device creator acceptance is still pending.

Setup uses a content-free FNA Game, SpriteBatch and code-defined 5×7 font atlas. It draws the warning, package choices, progress, errors and buttons directly; onboarding opens no native view controllers or document pickers. Worker completion is applied on the game update thread. SDL handles the outer game loop, window/input events and lifecycle. The setup device/window is disposed before original-game construction. Original game settings, photo selection and save paths retain their existing hooks.

The icon is resized from `assets/icon/icon-black.png`, the opaque square 1024-pixel source. iOS applies its own rounded mask; no border or baked corner rounding is added. The recipe supplies loose iPhone/iPad icon sizes and plist declarations, avoiding an unnecessary simulator-runtime requirement in Xcode's asset compiler.

## Audio implementation and local checks

`native/audio.c` calls libavformat/libavcodec/libavutil and libvorbis directly; it never starts FFmpeg or calls its CLI entry point. It accepts the pinned stereo 44.1 kHz WMA v2 format, queues decoded planar-float samples in a bounded FIFO, encodes Vorbis quality 5, flushes decoder/encoder, and muxes Ogg. Each conversion owns its state, supporting the shared preparer's three concurrent calls. The shared content verifier checks the Ogg header before accepting output. Conversion progress currently reports stage completion rather than native sample progress.

The native build disables programs, networking, GPL and nonfree components, and unneeded codecs. Source versions are FFmpeg `239f2c733d` (8.1.1), libogg 1.3.6, and libvorbis 1.3.7, with the same archive hashes as desktop. The generated SHA-256 identifies the combined static archive and is recorded in the content manifest's legacy converter-hash field. It is a build identity, not a reviewed iOS release pin. The current macOS check archive hash is recorded in the implementation log; an iOS archive must be built and reviewed separately.
