# Menu startup media-source adaptation

The supported original DLL has SHA-256 `7b819cb562826ae4d2592ff741877e76da0e57bfbe48192aabb79319fdb36823`. In `ZombiesWP7.custom.CustomMgr.Init(GraphicsDevice, ContentManager)` (method token `0x06000152`), the original IL body has SHA-256 `54407b733f8c2d7cdc67534f66899e99191731e2e0beeed8481bc673ff54f425`. At IL offset `0x0015`, it calls `Microsoft.Xna.Framework.Media.MediaSource.GetAvailableMediaSources()`.

During a staged menu run, that FNA call threw `NotImplementedException` on the background content-loading thread. The original code accepts an empty collection and skips phone media-library traversal. `GameplayPatcher` therefore changes only this call operand to `Port.Hooks.DesktopMediaSources.GetAvailableMediaSources()`, which returns an empty `IList<MediaSource>` and emits an informational trace. The original method's other instructions and control flow are retained. The .NET 10 hook DLL is pinned by SHA-256 `0da7b8604f5e40f609f1a1b92ff084b995ddc8eaded4be7c74172f28f7c11348`.

The patcher validates the supported XAP and original DLL, original method token/body hash, prior prepared DLL and manifest, exact old call signature and offset, and hook assembly identity/hash. It writes a new ignored prepared DLL and manifest, reopens the output to verify the call target, and never modifies the source DLL. A fresh staged run reached the animated menu and exited with code 0; see [menu bring-up](../docs/runtime/menu-bringup.md). This adaptation says only that the desktop has no phone media-library sources. It does not implement music playback or the other phone media APIs.
